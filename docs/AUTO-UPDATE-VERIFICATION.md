# Windows 自动更新验收（0.2.14w）

2026-10-21，针对“应用内自动更新是否有效”的实际检查。目标仓库为 `Cetirzine/Kiln-Windows`。

## 发现的问题

- 0.2.13w 的 PowerShell 替换脚本未将非终止错误转换为失败。临时副本缺失更新目录时，旧目录已移到备份，后续失败仍把成功标记设为 true，最终删除备份。报告：`artifacts/update-regression-94c07bfc2f6c4858b8faef8b38daf3ff/report.json`。未改用户安装。
- `Move-Item` 在失败时可能已创建部分目标目录，不能把它当作目录的原子重命名。替换为同一父目录内的 `Directory.Move`，并对目录、前缀及绝对路径做检查。
- Windows PowerShell 5.1 的无 BOM 脚本与部分启动参数处理不能可靠覆盖中文、方括号和单引号路径。脚本改用 UTF-8 BOM，文件操作使用字面路径，启动用 `ProcessStartInfo`。
- 实际 GitHub 下载连接在收到响应后超过两分钟没有数据，原下载流没有闲置超时。增加每次读取 30 秒闲置超时；转换为可重试超时，保留主动取消语义。
- 当前出口的匿名 GitHub API 配额实际耗尽，响应 403、remaining=0。增加官方 `/releases/latest` 重定向和同仓库 `.zip.sha256` 后备路径；必要时读取官方 Atom 说明，不要求用户提供 GitHub 令牌。
- 设置里的“立即检查”原本只跳到关于页。现在直接检查并禁用重复点击；网络失败会明确提示，不把请求超时当成用户取消。

## 已实现与验证

- 下载、校验和替换分别显示阶段；必须有有效 SHA-256。解压后检查应用产品/版本与必要文件，再复制到唯一的同卷临时目录。哈希、解压和复制在后台执行；取消会清理自己的临时目录。保留 Inno 卸载记录。
- 替换助手等待原进程退出，处理短暂文件占用；备份名唯一，失败恢复旧目录；启动命令失败或新进程在前三秒非零退出时也回滚。无法恢复时保留备份及日志，不删除旧版。游戏启动或运行时不开始更新，替换前再次检查。若配置的游戏目录等于或位于程序目录内，则拒绝整目录自动替换，提示使用安装包更新，避免覆盖游戏数据。
- 135 项核心回归通过，包含版本、ZIP 选择、草稿/预发布排除、摘要缺失/错误与官方网站后备校验。
- 11 项独立更新回归通过：缺少临时程序、锁定文件、无效 EXE、特殊路径、无关备份保留、非所属目录拒绝、坏哈希、取消和断流。报告：`artifacts/update-regression-4382812ccc664ac0bcee7ea41009e3b8/report.json`。
- 真实联网测试从 GitHub 读取最新正式版，将 0.2.12w 的隔离副本更新到已发布的 0.2.13w，保留卸载记录，等待拥有旧程序文件锁的进程退出，执行真正的替换脚本并重新启动已下载的 EXE。新 EXE 完成其全部 89 项 UI 回归。报告：`artifacts/update-live-cacc696d99e84258bee6c519f164757f/report.json`；测试目录包含中文、方括号和单引号。
- 0.2.14w 自包含程序完成 94 项 UI 检查；新增检查直接调用正式更新弹窗的创建方法，分别验证立即更新、查看发布页、稍后的返回动作，并检查游戏数据目录保护。此项不执行安装，不访问真实安装目录。
- Modrinth / CurseForge 搜索、文件版本、下载、SHA-1、指纹及真实 Mod 导出引用再次通过，确认下载超时改动未破坏这些流程。
- 正式发布 0.2.14w 后，再使用程序自身的检查代码验证：从 0.2.13w 正确发现 0.2.14w，当前 0.2.14w 不重复提示；强制使用官方网站后备也发现同一版本。两条路径摘要一致，为 `1bd3c6c271c5905398a6572c482f3b167aee024225317f85833c250bed4e3bf6`，ZIP 大小 69,489,802 bytes，发布说明成功读取。

## 验证边界

### 当前用户安装的补充实测

- 2026-10-21，再次检查实际运行进程，路径为 `D:\Kiln\Kiln.exe`，文件版本及关于页均为 `0.2.10w`。通过应用界面点击「关于 → 检查更新」，实际弹出 `HTTP 403: https://api.github.com/repos/Cetirzine/Kiln-Windows/releases/latest`。已关闭错误提示，没有更新或关闭用户程序。
- 用 0.2.14w 更新检查代码执行 `--updater-check 0.2.10w`：正常入口与强制官方网站后备均识别到 `0.2.14w`，摘要均为 `1bd3c6c271c5905398a6572c482f3b167aee024225317f85833c250bed4e3bf6`，ZIP 为 69,489,802 bytes；当前版本不重复提示。GitHub CLI 同时确认该 Release 为已发布的正式版，四个附件均为 uploaded。
- 再次运行独立更新回归，11 项全部通过，报告：`artifacts/update-regression-3cf7fc0c06e042a69f25f44ad3242c43/report.json`。本轮未执行真实安装目录的替换或整套 UI 自动安装。结论是当前运行的旧版更新检查失败；已发布修复版的发现路径及隔离替换回归通过，建议手动安装修复版一次。

试图启动带标记的副本、通过应用内按钮自动完成自更新的额外验证，被工具自动审批检查拒绝；返回原因只有“blocked by policy”，没有细节。没有换入口绕过该拒绝，相关自动执行模式已移除。更新弹窗与更新链路因此是分别验证的，不能宣称完成了该项单次 UI 自动安装验收。

测试没有接管用户实际安装、账号或 PCL2 配置。旧版程序的更新脚本不会因发布新版而自动变好；建议手动安装 0.2.14w 一次，再使用其后续自动更新流程。完整游戏启动与全页 1:1 验收仍见 `PORT-PARITY.md`。

实现参考 GitHub 官方的[最新 Release 链接](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases)及[API 速率限制](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)。
